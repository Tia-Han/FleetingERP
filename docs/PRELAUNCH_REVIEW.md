# 上线前代码审查（2026-09-29）

## 结论与范围

本项目确实包含网页（public）、微信小程序（miniprogram）和共享的 Express/SQLite 后端。当前仍为测试阶段。网页与小程序各自维护页面与金额展示逻辑，共享 API、权限和数据库，因此接口契约与跨端回归是后续迭代的重点。

本轮以 0793f5dc44f69be629ccf374bc2fb51779144ab2 为基础。审查覆盖路由权限、库存写入、订单与客户关联、备份恢复、请求重试、网页页面生命周期、小程序数据提交及模板事件绑定。所有一方 JavaScript/JSON 和网页资源引用执行静态检查，小程序全部注册页面执行事件方法存在性检查。静态遍历不等于每条业务路径都经过人工或实机验收。

**不能据此宣布正式上线验收完成。** 小程序尚未配置和实机验证，部分长期风险仍待处理，详见后文。旧审查文档保留历史背景；当前功能边界以本文件和实际代码为准。

## 本轮已修复

| 问题 | 修复与影响 |
|---|---|
| 场所权限将销售汇总路径误当订单详情 | 详情鉴权显式绑定对应路由；列表、汇总与写入分别限制场所 |
| 旧版数据库备份无法跨新增权限字段恢复 | 仅兼容已知可补充字段和内部去重表，其他结构仍严格验证 |
| 恢复可能导入没有启用管理员的备份 | 恢复前拒绝，避免恢复后无人能管理 |
| 小程序修改商品丢失 SKU 身份 | 更新保留原 SKU ID，修正分装属性读取 |
| 网页新增同名客户可能选中旧客户 | 根据创建接口返回的 ID 获取客户，禁止模糊名称猜测 |
| 批量出库部分失败，小程序却显示全部成功并清空 | 后端返回原始行索引，两端保留失败行，已成功行不再重复提交 |
| 小程序调拨历史误分类、详情访问错误、数量重复负号 | 与统一历史接口及调拨详情对齐 |
| 小程序修改数量后折扣金额未重算 | 每次汇总按当前数量重新计算，展示金额在 JS 中格式化 |
| 旧登录请求返回 401 可能清除新会话 | 响应处理前比对请求所属 token |
| 搜索旧结果覆盖新输入，切页后仍展示 | 搜索请求序号、输入值及节点有效性校验，释放关闭事件 |
| 网页快速切页时旧请求更新已移除的页面 | 读请求绑定页面版本、页签及最新请求序号 |
| 库存品类取消编辑时将名称作为 HTML | 使用文本赋值 |
| 小程序模板含不存在的事件方法 | 移除错误绑定，增加全页面绑定检查 |

分装按业务决定暂不上线：隐藏网页快捷入口、拦截页面导航，默认拒绝创建分装订单。保留历史查询和数据；不要在部署环境中设置 ENABLE_SPLIT=true。该开关仅供未来实现和测试使用，开启前必须解决余液计量、成本和库存模型。

## 防止改 A 破坏 B

新增接口与模板契约测试、跨角色“入库→调拨→销售”的库存守恒与重试测试、备份版本兼容测试、批量部分失败行映射测试、页面异步响应归属测试和小程序折扣/SKU 身份测试。GitHub Actions 配置 Node 22/24 两个版本运行 npm ci 和 npm test；必须以实际 Actions 结果确认通过，不能仅凭配置存在判断。

临时数据库 Chrome 验证：管理员登录、动态门店角色、三个相同请求只创建一个场所、新增用户、11 个页面遍历、同名客户关联、分装拒绝；页面异常列表为空。该验证不是全业务穷举，也没有验证真实摄像头或微信设备。

## 仍需处理的风险

| 优先级/阶段 | 风险与处理方向 |
|---|---|
| 正式多人使用前 | 2026-09-30 已增加商品/SKU 内容版本校验与 409 冲突提示；需在部署后完成双账号现场验收，其他主数据编辑尚未扩展该保护 |
| 正式数据积累前 | 历史单据关联当前商品/规格/场所名称，改资料可能改变历史展示；需为新单据保存业务快照和稳定操作者标识，并明确旧单据展示规则 |
| 小程序发布前 | 未完成微信开发者工具编译、真机、AppID、合法域名、权限入口及网络超时验收；不得将源码静态测试当作发布验收 |
| 数据规模扩大前 | 部分页面读取全量商品/客户/历史，客户明细存在逐条查询；需统一分页和服务器搜索，建立有代表性数据量的延迟基线 |
| 数据规模扩大前 | SQLite 同步查询及大导出会占用 Node 事件循环。当前单实例便于事务一致性；不能直接增加 PM2 多实例代替性能设计 |
| 持续迭代前 | 数据库升级仍依赖启动时补字段/索引，缺少明确迁移版本账本；应逐步引入版本化迁移与跨版本恢复演练 |
| 长期运行前 | 幂等请求结果持久化表缺少保留期限协议；需先定义重试有效期再清理，直接删除会让迟到重试重复执行 |
| 财务口径确认前 | 金额存储仍有 REAL 字段，历史成本/利润口径需要业务确认；当前测试不等于会计结算精度和成本政策验证 |
| 运维验收 | 需核实 Nginx 转发地址与登录限流来源、PM2 日志轮转、异机备份和恢复演练。当前无法仅由本地代码证明云端配置正确 |

本轮没有更改上述业务政策、清理线上历史数据或执行云端配置修改。这些条目是后续工作的明确清单，不是已实现功能。

## 部署与同步边界

本轮不修改 package.json/lockfile、数据库 schema 和环境文件；包含后端、网页、小程序、测试及 CI 更新，因此服务器需要受控重启。部署前确认当前提交、工作区干净、实际数据库路径和最终备份；先在临时数据库跑测试，再切换代码，验证监听地址/健康检查/业务记录一致性，成功后保存 PM2。不要重复旧数据库迁移或初始化种子脚本。

服务器上一次已确认版本为 0793f5d，最终备份 本地运维记录中的已验证备份目录，PM2 保存及自启动状态已通过用户回传确认。新版本是否已部署以新的服务器回传为准；GitHub 更新不等于服务器更新，小程序源码更新也不等于微信发布。
